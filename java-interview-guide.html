Difference between abstract class and interface
Comparison

An abstract class is a base class with some common state or shared code. An interface is mainly a contract: it says what a class can do. Since Java 8, interfaces can have default and static methods, but they are still not meant to hold object state like a normal class.

abstract class Vehicle {
    protected String number;

interface Trackable {
    String currentLocation();

class Taxi extends Vehicle implements Trackable {
    Taxi(String number) { super(number); }

}
Can we achieve multiple inheritance in Java?

Java does not allow a class to extend multiple classes because two parent classes may have the same method or state, and that creates confusion. But Java supports multiple inheritance of type through interfaces.

interface Printable { void print(); }
interface Scannable { void scan(); }

class MultiFunctionPrinter implements Printable, Scannable {
    public void print() { System.out.println("Printing"); }
    public void scan() { System.out.println("Scanning"); }
}
Interview line: "Java avoids multiple class inheritance but allows a class to implement multiple interfaces, so we get flexibility without the diamond problem of shared state."
Explain OOP concepts with real-time examples

OOP means modeling software around objects that have data and behavior.

  • Encapsulation: Keep data private and expose controlled methods. Example: bank balance cannot be changed directly.
  • Abstraction: Show what is needed and hide complex details. Example: you call payment.pay() without knowing bank network details.
  • Inheritance: Reuse common behavior. Example: Car and Bike inherit from Vehicle.
  • Polymorphism: Same method call behaves differently. Example: Payment can be card, UPI, or wallet payment.
interface Payment {
    void pay(double amount);
}

class UpiPayment implements Payment {
    public void pay(double amount) {
        System.out.println("Paid by UPI: " + amount);
    }
}

class CardPayment implements Payment {
    public void pay(double amount) {
        System.out.println("Paid by card: " + amount);
    }
}

Why is String immutable?

String is immutable because once created, its value cannot change. This makes strings safe for sharing, caching, security, and hashing.

  • String pool: Same string literals can be reused safely.
  • Security: File paths, URLs, class names, and credentials cannot be changed silently after validation.
  • Thread safety: Multiple threads can read the same string without locking.
  • HashMap keys: Hash code remains stable after insertion.
String name = "Java";
String changed = name.concat(" 21");

System.out.println(name);    // Java
System.out.println(changed); // Java 21
Difference between == and equals()

== compares references for objects. equals() compares logical value if the class has implemented it properly.

String a = new String("Java");
String b = new String("Java");

System.out.println(a == b);      // false, two different objects
System.out.println(a.equals(b)); // true, same text value
For primitives, == compares value. For objects, use equals() when you care about business value.
hashCode() and equals(): why both are needed?

Collections like HashMap and HashSet first use hashCode() to find a bucket, then use equals() to check the exact object. If two objects are equal, they must return the same hash code.

class Employee {
    private final int id;
    private final String name;

    Employee(int id, String name) {
        this.id = id;
        this.name = name;
    }

    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Employee other)) return false;
        return id == other.id;
    }

    public int hashCode() {
        return Integer.hashCode(id);
    }
}

If you override equals() but not hashCode(), hash-based collections may fail to find your object even though it looks equal.

Can we override a static method?

No. Static methods belong to the class, not the object. If a child class declares a static method with the same signature, it is method hiding, not overriding.

class Parent {
    static void show() { System.out.println("Parent"); }
}

class Child extends Parent {
    static void show() { System.out.println("Child"); }
}

Parent p = new Child();
p.show(); // Parent, because static method is resolved by reference type

What is a transient variable?

transient tells Java serialization to skip that field. Use it for sensitive data or values that can be recalculated.

class UserSession implements Serializable {
    private String username;
    private transient String password; // will not be serialized
}
Marker interface examples

A marker interface has no methods. It marks a class for special treatment by JVM, libraries, or framework code.

  • Serializable: object can be serialized.
  • Cloneable: object allows clone behavior.
  • Remote: used in RMI.

Modern Java often prefers annotations for this kind of metadata, but marker interfaces still exist in core Java.

HashMap internal working: Java calculates the key hash, finds a bucket index, stores the entry there, and compares keys using equals() if collisions happen. When the map grows beyond load factor, it resizes. In Java 8+, a heavily collided bucket can become a tree for better lookup.

Important HashSet warning: If you add a mutable object to a HashSet and later change the field used in hashCode(), the set may not find it again. Keep set keys immutable.

Optional: how to avoid NullPointerException effectively

Optional is a return type that tells the caller "this value may be absent." It is cleaner than returning null from service methods.

Optional<User> user = userRepository.findByEmail(email);

String displayName = user
    .map(User::getName)
    .filter(name -> !name.isBlank())
    .orElse("Guest");

Do not overuse it for fields, method parameters, or every local variable. Use it mainly at boundaries where absence is a normal result.

JVM memory, garbage collection, memory leak, OOM, compiler, JIT, ClassLoaders

The JVM runs Java bytecode. The compiler converts .java to .class. The JVM interprets bytecode first and uses JIT compilation for hot code paths so frequently used code becomes native machine code.

AreaWhat it stores
HeapObjects and arrays. Main GC area.
StackMethod calls, local variables, references. One stack per thread.
MetaspaceClass metadata.
PC register/native stackExecution position and native calls.

GC: Garbage collection removes objects no longer reachable from live references. Common collectors include G1, ZGC, Shenandoah, Parallel GC, and Serial GC.

OutOfMemoryError: Can happen due to real traffic growth, unbounded caches, memory leaks, too many threads, large payloads, or wrong heap sizing. Debug using heap dumps, GC logs, jcmd, jmap, and monitoring.

ClassLoaders: Bootstrap loads core Java classes, Platform loads platform modules, Application loads app classes. Custom classloaders are used by app servers, plugins, and frameworks.

Race condition, deadlock, volatile, AtomicInteger, synchronized, ThreadLocal, ExecutorService

A race condition happens when multiple threads access shared data and the result depends on timing. Protect shared mutable state or avoid sharing it.

ToolUse it whenLimit
synchronizedYou need mutual exclusion and visibilityCan block threads
volatileOne thread writes, others must see latest valueDoes not make compound actions atomic
AtomicIntegerYou need lock-free atomic countersGood for simple atomic operations only
ThreadLocalPer-thread data like correlation idMust clear it in thread pools to avoid leaks
class SafeCounter {
    private final AtomicInteger count = new AtomicInteger();

    int increment() {
        return count.incrementAndGet();
    }
}

Deadlock: Two threads wait forever for locks held by each other. Prevent it by using consistent lock order, timeouts, smaller lock scopes, and avoiding nested locks where possible.

Executor sizing: CPU-bound pools are close to CPU core count. I/O-bound pools can be larger because threads wait on network or database calls. With Java 21 virtual threads, blocking I/O becomes cheaper, but database and downstream limits still matter.

CompletableFuture, CountDownLatch, Producer-Consumer

CompletableFuture is used for async pipelines. It helps combine async tasks, handle errors, and add timeouts.

CompletableFuture<User> userFuture =
    CompletableFuture.supplyAsync(() -> userService.findUser(id))
        .orTimeout(2, TimeUnit.SECONDS)
        .exceptionally(ex -> User.guest());

CountDownLatch lets one thread wait until other tasks finish. Producer-consumer is usually implemented with BlockingQueue.

BlockingQueue<String> queue = new ArrayBlockingQueue<>(100);

// producer
queue.put("order-1");

// consumer
String order = queue.take();

SOLID and common design patterns

SOLID is a set of habits that keep code easier to change.

  • S: One class should have one main reason to change.
  • O: Add new behavior by adding code, not editing many old classes.
  • L: Child classes should work wherever parent type is expected.
  • I: Small interfaces are better than one giant interface.
  • D: Depend on abstractions, not concrete classes.
PatternUse case
SingletonOne shared instance, like config holder. In Spring, singleton beans are default.
FactoryCreate object based on type, such as payment method.
BuilderCreate complex immutable objects cleanly.
AdapterMake a third-party API fit your app interface.
StrategySwap algorithms at runtime, like discount calculation.
ObserverNotify listeners when something changes.

How does Spring Boot auto-configuration work internally?

Spring Boot checks what classes are on the classpath, what beans already exist, and what properties are set. Then it creates sensible default beans. It uses conditional annotations like @ConditionalOnClass, @ConditionalOnMissingBean, and @ConditionalOnProperty.

@Configuration
@ConditionalOnClass(DataSource.class)
@ConditionalOnProperty(name = "app.db.enabled", havingValue = "true")
class DatabaseConfig {
    @Bean
    DataSource dataSource() {
        return createDataSource();
    }
}

@SpringBootApplication combines:

  • @EnableAutoConfiguration

That means it marks the main configuration class, enables Boot auto-config, and scans packages for Spring components.

IoC container, dependency injection, bean lifecycle, scopes, @PostConstruct

The IoC container creates objects, wires dependencies, manages lifecycle, and gives those objects to your code. Dependency Injection means the class receives dependencies from outside instead of creating them itself.

ScopeMeaning
singletonOne bean per Spring container. Default.
prototypeNew bean whenever requested.
requestOne bean per HTTP request.
sessionOne bean per HTTP session.

Bean lifecycle is roughly: instantiate, inject dependencies, call aware callbacks, call post-processors, call @PostConstruct, use bean, call destroy callbacks on shutdown.

If @PostConstruct throws an exception, bean creation fails and usually the application startup fails.

@Qualifier vs @Primary

Use @Primary when one bean should be the default choice. Use @Qualifier when the injection point must ask for a specific bean.

@Service("smsNotifier")
class SmsNotifier implements Notifier {}

@Service("emailNotifier")
@Primary
class EmailNotifier implements Notifier {}

class AlertService {
    AlertService(@Qualifier("smsNotifier") Notifier notifier) {}
}

@Value is fine for one or two values. @ConfigurationProperties is cleaner for grouped config because it gives type-safe binding.

If it works locally but fails in production, compare configuration, environment variables, profiles, database access, network rules, secrets, JVM version, container limits, and dependency versions. Read startup logs first; Spring usually tells you which bean or property failed.

int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> index = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        int need = target - nums[i];
        if (index.containsKey(need)) return new int[] { index.get(need), i };
        index.put(nums[i], i);
    }
    return new int[] { -1, -1 };
}

Set<Integer> duplicates(int[] nums) {
    Set<Integer> seen = new HashSet<>();
    Set<Integer> dup = new HashSet<>();
    for (int n : nums) if (!seen.add(n)) dup.add(n);
    return dup;
}

Merge two sorted linked lists 
ListNode merge(ListNode a, ListNode b) {
    ListNode dummy = new ListNode(0);
    ListNode tail = dummy;

    while (a != null && b != null) {
        if (a.val <= b.val) {
            tail.next = a;
            a = a.next;
        } else {
            tail.next = b;
            b = b.next;
        }
        tail = tail.next;
    }
    tail.next = (a != null) ? a : b;
    return dummy.next;
}
Sliding window maximum and interval scheduling

Sliding window maximum uses a deque that keeps useful indexes in decreasing order. Minimum platforms/interval scheduling usually sorts start and end times, then counts overlaps.

int minPlatforms(int[] arrival, int[] departure) {
    Arrays.sort(arrival);
    Arrays.sort(departure);
    int i = 0, j = 0, used = 0, max = 0;
    while (i < arrival.length) {
        if (arrival[i] <= departure[j]) {
            used++;
            max = Math.max(max, used);
            i++;
        } else {
            used--;
            j++;
        }
    }
    return max;
}

10. Real-World Production Scenarios

These are not definition questions. The interviewer wants to see how you think under pressure.

Slow APIs, startup, downtime, consistency
API was fast in testing but times out in production after a few hours

I would check whether something grows over time: memory, thread count, DB connections, cache size, queue lag, file handles, or blocked threads. Then I would compare latency, error rate, GC pauses, heap usage, thread pool usage, and database query time over the same period.

Common causes: memory leak, connection leak, unbounded cache, slow query under real data volume, downstream timeout, thread pool exhaustion, or GC pressure.

CPU is low but API latency is high

Low CPU usually means the app is waiting, not computing. I would check DB locks and slow queries, external service latency, connection pool exhaustion, thread pool queues, network latency, DNS, and Kafka/queue lag.

Endpoint becomes slower over time until restart fixes it

This often points to a leak or accumulation problem: memory leak, connection leak, cache growing without eviction, thread leak, or data structure growing in memory. Restart clears memory temporarily, but the real fix is to identify the growing resource and add proper cleanup, limits, or pooling.

New version increases response time by 30 percent

First protect users: rollback, reduce traffic to the new version, or disable the feature flag. Then compare metrics between versions: DB calls, external calls, query plans, CPU, memory, GC, thread pools, and traces. If using canary, stop rollout before all traffic is affected.

Spring Boot starts slowly in production but quickly locally

Check active profiles, config server latency, database connectivity, DNS, cloud metadata calls, classpath size, migration scripts, bean initialization doing network calls, low CPU/memory limits, and slow secret manager calls.

Critical bug saves wrong data. How to fix without downtime?

Stop the damage first: feature flag off, block bad path, or route traffic to old version. Deploy a hotfix using rolling/canary release. Add data validation and idempotency if missing. Then run a controlled data correction script with backup, audit, and verification.

Third-party API fails intermittently

Use timeouts, retries with backoff, circuit breaker, fallback, cache, queue for async retry, and clear error response. Also monitor the third-party dependency separately so the team knows it is not an internal outage.

Memory leak in production, pod keeps getting killed

Capture heap dump before the pod dies, enable GC logs/JFR if safe, check memory trend, compare object counts, and find retainers in Eclipse MAT. Temporarily increase memory or restart policy only as a short-term mitigation. Real fix is usually limiting cache, closing resources, removing static references, or fixing collection growth.

Kafka consumers are lagging

Check whether processing is slow or consumption capacity is low. Increase partitions and consumers if possible, tune batch size and poll records, optimize downstream DB/API calls, avoid long blocking work inside consumer thread, and commit offsets only after safe processing.

Payment deducted but confirmation failed

Use a transaction state machine and reconciliation. The payment should have a unique transaction id. If confirmation fails, mark it pending, retry safely, query payment gateway status, and either confirm order or reverse/refund. Never rely only on one HTTP response for money flow.

Config server changed but services did not pick it up

Check whether Spring Cloud refresh is enabled, whether the property is refresh-scoped, whether bus refresh is configured, and whether the service is using the correct profile/label. You can trigger refresh endpoint or publish a refresh event through Spring Cloud Bus. Some properties still need restart because they are read during bean creation.

synchronized block vs synchronized method

A synchronized method locks the whole method on the object. A synchronized block lets you lock only the small critical part, so it is more flexible and usually better for performance.

class Wallet {
    private final Object lock = new Object();
    private int balance;

    void add(int amount) {
        validate(amount); // no lock needed
        synchronized (lock) {
            balance += amount;
        }
    }
}
Java Memory Model and happens-before relationship

The Java Memory Model explains when changes made by one thread become visible to another thread. A happens-before relationship is a visibility guarantee. For example, unlocking a synchronized block happens-before another thread locks the same monitor.

Common happens-before examples: thread start, thread join, volatile write followed by volatile read, synchronized unlock followed by lock, and completing a Future before reading its result.

How to make a class thread-safe?

Start by asking: does this class have shared mutable state? If yes, protect it. Good choices are immutability, synchronized blocks, locks, atomic classes, concurrent collections, or avoiding shared state completely.

// Remove duplicates from sorted array, allowing at most two
int removeDuplicates(int[] nums) {
    int write = 0;
    for (int n : nums) {
        if (write < 2 || n != nums[write - 2]) {
            nums[write++] = n;
        }
    }
    return write;
}

// Search in rotated sorted array
int search(int[] nums, int target) {
    int l = 0, r = nums.length - 1;
    while (l <= r) {
        int m = l + (r - l) / 2;
        if (nums[m] == target) return m;
        if (nums[l] <= nums[m]) {
            if (nums[l] <= target && target < nums[m]) r = m - 1;
            else l = m + 1;
        } else {
            if (nums[m] < target && target <= nums[r]) l = m + 1;
            else r = m - 1;
        }
    }
    return -1;
}

Trees: traversals, diameter, LCA, balanced tree check

Tree traversal types are inorder, preorder, postorder, and level order. Diameter is the longest path between any two nodes. LCA is the lowest node that has both target nodes under it. A balanced tree means left and right subtree heights do not differ too much, usually by more than one for height-balanced problems.

int height(TreeNode root) {
    if (root == null) return 0;
    int left = height(root.left);
    int right = height(root.right);
    if (left == -1 || right == -1 || Math.abs(left - right) > 1) return -1;
    return 1 + Math.max(left, right);
}

boolean isBalanced(TreeNode root) {
    return height(root) != -1;
}
